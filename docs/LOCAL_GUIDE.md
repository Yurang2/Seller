# 로컬 사용 안내

현재 범위는 M0·M1·M2: 상품 조사부터 원가·가격 결정, 채널 등록 상품 기록과 판매 중 전환까지입니다. 실제 주문 수집·정산·자동화는 아직 없습니다.

## 처음 열면

1. `pnpm db:migrate:local`, `pnpm dev`를 실행하고 http://127.0.0.1:5173 을 엽니다.
2. 홈에서 **초기 조사 기록 불러오기**를 누릅니다. 상품 4개, 공급처 3개, 오퍼 4개, 배송 경로 2개, 요건 프로필 2개와 각 13개 항목, 결정·할 일·개념집을 가져옵니다. 다시 눌러도 같은 상품이 늘어나지 않습니다.
3. 홈의 D-01 사업 모델 검토부터 확인합니다. 미결정을 유지하면서 조사할 수 있습니다.

## 상품 하나를 조사하는 순서

- **상품 조사** 보드에서 상품을 엽니다. 캐릭터·옵션·요건 프로필을 연결합니다.
- **판매 요건**에서 항목의 답변 근거를 먼저 입력하고, 판단 이유와 함께 항목 결과를 저장합니다. 경쟁사 판매 사례만으로 통과할 수 없습니다. 답변 근거를 수정하면 재판정이 필요합니다.
- **공급처·견적 → 오퍼**에서 동일 옵션·수량의 실결제가를 기록합니다. 가격은 현지 통화로 입력합니다. CNY 입력 59.9는 내부 5,990 최소 단위로 저장됩니다.
- 가격·배송비를 확인으로 기록하려면 실제 증빙 파일을 첨부합니다. 첨부가 없으면 추정으로 저장되며 메시지가 나타납니다.
- **배송 비교 → 배송 구간**에서 실제 각 구간의 비용, 소포당·개당·주문당·kg당 기준을 기록합니다. 국제 견적에 국내 택배가 포함돼 있으면 포함 항목을 선택합니다. 별도 국내 구간과 겹치면 경고가 남습니다.
- **설정 → 환율**, 상품의 가정 판매가·고객 청구 배송비·수량·수수료·월 비용, 판매 채널의 수수료를 채웁니다. 모르면 미확인으로 둡니다. 월 비용도 모르는데 0으로 채우지 않습니다.
- 상품의 **원가·배송 경로 비교**에서 같은 오퍼에 연결된 경로를 비교합니다. 미확인 목록의 버튼으로 해당 근거를 바로 편집할 수 있습니다.
- 저장 이유를 적고 **스냅샷 저장**을 누릅니다. 이후 입력이 바뀌어도 저장된 원가는 바뀌지 않으며 “현재 값과 다름”으로 표시됩니다.
- 상품의 **단계 변경**은 필수 요건을 검사합니다. 가격 결정 단계에서는 이유·대안·재검토 조건을 기록합니다. 필수 사업 준비를 마치기 전 등록 준비 단계로 갈 수 없습니다.

초기 조사에는 확인되지 않은 실제 비용이 많으므로 계산 결과가 “계산 불가”인 것이 정상입니다. CALC-EX1 가상 데이터는 테스트에만 쓰며 실제 상품 원가로 입력하지 않습니다.

## 기억·근거·백업

- 노트·결정·할 일에서 기록을 남기면 홈의 이어서 하기에 표시됩니다. 모든 변경에는 이유와 변경 전·후 이력이 남습니다.
- **근거·재확인**에서 기한 지난 항목을 볼 수 있습니다. 조건이 해결되면 관련 파생 작업이 자동으로 완료됩니다. 이는 내부 계산 규칙이며 외부 자동화 연동이 아닙니다.
- **조사 파일 가져오기**는 템플릿의 열 순서·ID를 유지한 XLSX를 읽습니다. 미리보기 후 적용하며 행별 실패 이유가 남습니다. 외부 ID는 같은 내부 ID로 매핑됩니다. `-EX1` 가상 행과 원가계산 수식은 가져오지 않습니다.
- **백업·복원**에서 JSON·CSV·첨부 원본 ZIP을 내려받습니다. 개인정보 마스킹이 기본이며 첨부 파일은 원본입니다. 복원은 미리보기 후 적용합니다.
- 개발자 검증용 `pnpm backup:verify`는 로컬 저장소를 독립된 빈 임시 D1/R2에 실제 복원하여 행·첨부 바이트를 비교합니다. 성공했을 때만 `backup_verified`가 완료됩니다. 결과는 `work/backup-verification.json`에 남습니다. 운영 원격 검증을 대신하지 않습니다.

## 지금 보류한 범위

Cloudflare 배포·전체 경로 Access 로그인 검증, M2 이후 판매 등록 및 주문 운영, 외부 API·자동 백업 스케줄은 미연동입니다. 로컬 서버는 종료하면 접속되지 않으며 다시 `pnpm dev`로 켭니다. 데이터는 같은 로컬 저장 경로에 유지됩니다.

## 채널에 올리고 판매 중으로 기록하기 (M2)

1. 사업 준비 체크리스트의 필수 항목(사업자 등록, 통신판매업 신고, 채널 계정, 정책 문구 등)을 근거와 함께 완료합니다. 홈의 "판매 개시까지 남은 것"이 비어야 합니다.
2. 상품이 등록 준비 단계여야 합니다(요건 통과·조건부, 원가 스냅샷, 가격 결정 기록).
3. 채널·등록 상품 → 채널 화면의 "상품 올리기(수동)" 절차대로 판매자 센터에 올립니다. 이미지는 직접 촬영본만 씁니다.
4. 등록 상품 기록을 만들고 채널 상품 번호, 등록 판매가(결정 판매가와 같아야 함), 이미지 출처, 노출 확인일을 적은 뒤 상태를 판매 중으로 바꿉니다.
5. 상품 단계를 판매 중으로 변경합니다. 판매 중 등록 상품이 없으면 막힙니다.
6. 주문은 "주문 처리(수동)" 절차대로 일지에 남깁니다. 주문 기능은 다음 단계입니다.

삭제한 기록은 목록 하단 "삭제된 기록 보기·복구"에서 이유를 적고 되살릴 수 있습니다.
